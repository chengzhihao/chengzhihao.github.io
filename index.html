LLM分解任务

LLM分解任务

用户发问

我的提问信息是： “ 采用cli命令行， 每个节点自动后自动发消息给所有在线节点，每个节点上线后，广播自己的在线信息给其他节点，去中心化。 每个节点另外所有节点5分钟没有心跳，即认为下线了，请认真设计一下。”

看看LLM是如何来分析这个问题的？

LLM的思考过程

原始需求：”每个节点启动后自动发消息给所有在线节点，去中心化”

         ↓ 拆解 ↓

- 自动发消息 → 需要定时任务

- 所有在线节点 → 需要知道”谁在线”

- 去中心化 → 不能有中心服务器

- 节点上线/下线检测 → 需要心跳机制

- 5分钟无心跳即下线 → 需要超时检测

LLM 提取信息里的关键信息，而且， 它能够依据上下文， 将 “每个节点自动后” ， 修改为 “每个节点启动后”， 并反馈给用户。

然后， LLM 会根据以上信息， 在它模型大脑里， 继续思考和推演过程，直至拿到最终结果。 LLM训练的好坏，决定了结果的正确性。

LLM与人类比较

思考程度

人类是线性递归的：
- 必须一步一步思考
- 但可以随时回溯、修正
- 大脑容量有限，一次只能想几件事
- 工作记忆限制：只能同时处理7±2个概念

LLM是平行激活的：
- 瞬间”看到”所有相关知识
- 没有工作记忆限制
- 所有相关信息同时激活
- 但可能缺乏深度推理

成长路径

人类成长过程

  • 看书学习、体育运动，社会互动
  • 行为约束，规范条约，以及社会中所见所闻，所触所想而形成的固有经验
  • 人类有具备高级情感，是区别于其他一切低级动物最根本的特征
  • 依据老话 “活到老，学到老”，就明白人的知识储备是有限的， 且知识和经验，是会老化的，所以要时常更新

LLM成长过程

  • 喂过一大堆数据，这些数据来源是相关论文摘要、技术博客片段、以及各种论坛和资讯
  • 不明白经验为何物， 它理解的关键在于文本关联，当然根据模型的各种数据、历史经验，得到的经验可能更客观
  • 无情感，通过模型反复训练即算法更新，让自己跟人类沟通起来显得那么有“情感”

Claude Code and Opus 4.5有多牛？

Top engineers at Anthropic, OpenAI say AI now writes 100% of their code—with big implications for the future of software development jobs

At Anthropic—an AI lab building some of the world’s most advanced models—engineers are no longer writing the code that powers their products; they’re outsourcing it to AI. The head of Anthropic’s Claude Code, Boris Cherny, has announced he hasn’t written any code in more than two months.

In a post on X, Cherny said 100% of his code is now written by Anthropic’s Claude Code and Opus 4.5. Across the rest of the company, he says “pretty much 100%” of code is also AI-generated.

“For me personally, it has been 100% for two+ months now, I don’t even make small edits by hand,” Cherny wrote in a post on X responding to AI researcher Andrej Karpathy. “I shipped 22 PRs (pull requests) yesterday and 27 the day before, each one 100% written by Claude.”

The comments echo earlier remarks by Anthropic CEO Dario Amodei at the World Economic Forum earlier this month, where he noted that some engineers at his company have stopped writing code themselves and instead rely on AI models to generate it while they focus on editing. At Davos, Amodei predicted that the industry may be just six to twelve months away from AI handling most or all of software engineering work from start to finish.

Cherny isn’t the only prominent engineer to announce they have largely abandoned manual coding. Roon, a popular pseudonymous account on X written by an OpenAI researcher, also said in a post on X that he no longer writes any of his own code. “100%, I don’t write code anymore,” the user wrote when asked what percentage of his coding is done by AI models. In a separate post, he added: “Programming always sucked. It was a requisite pain for ~everyone who wanted to manipulate computers into doing useful things, and I’m glad it’s over.”

这段话的意思是：

在“阿尼普蒂克”这家人工智能实验室（其正在开发一些全球最先进的模型）中，工程师们不再编写驱动其产品的代码；而是将这一工作交由人工智能来完成。阿尼普蒂克公司“Claude Code”项目的负责人鲍里斯·切尔尼宣布，他已经超过两个月没有编写任何代码了。

在一篇发布于 X 平台的帖子中，切尔尼表示，他目前所有的代码均由安托里普公司的Claude Code和 Opus 4.5 生成。而在公司的其他部门，他表示“几乎 100%”的代码也是由人工智能生成的。

切尔尼在推特上的一篇帖子中这样写道：“就我个人而言，这种情况已经持续了两个多月了，我甚至都不再手动进行小的修改了。”他是在回应人工智能研究者安德烈·卡帕西时发表上述言论的。“昨天我提交了 22 个 PR（拉取请求），前天又提交了 27 个，每一项都是由克劳德完全完成的。”

这些评论与安托普里公司首席执行官达里奥·阿莫埃伊本月早些时候在世界经济论坛上发表的言论相呼应。当时他指出，该公司的一些工程师已经不再自己编写代码，而是依靠人工智能模型来生成代码，而他们则专注于编辑工作。在达沃斯会议上，阿莫埃伊预测，该行业可能在六到十二个月内就能实现人工智能全面接管软件工程的所有环节。

切尔尼并非是唯一一位宣布已基本放弃手动编程的知名工程师。在 X 平台上一个颇受欢迎的匿名账号“Roon”（由一位 OpenAI 研究人员所写）也曾在 X 上发文称，自己不再编写任何个人代码了。“百分之百，我不再写代码了，”当被问及自己编码工作有多少是由 AI 模型完成时，该用户写道。在另一篇帖子中，他还补充道：“编程一直都很糟糕。对于想要让计算机完成有用任务的每个人来说，它都是必要的痛苦经历，我很高兴它已经结束了。”

程序员该咋办

AI确实很好， 但对于指挥AI来整体完成全套软件开发的个体“总工” 要求也非常高，一般人达不到， 所以，未来这方面的人才需求量只增不减，程序员应该跟随潮流，把这些工具先应用起来， 未来要“总工“， 也仍然需要 AI时代的“搬运工”。不跟随时代学习AI技术的程序员， 是真的会被淘汰的， 绝不危言耸听。 建议可以去使用目前爆火的AI编程工具， 你就会亲身感受到的。

理解AI重要概念

如今，AI 技术层出不穷，每天都能看到很多的资讯和工具诞生，但最根本的本质离不开 LLM、agent、mcp, skills。

下面通过一个简单示例来说明。 （咨询deepseek，给了我一个例子，大致上说明了 LLM、agent、mcp、skills

之间的关系）

LLM（大语言模型）：天才厨神“小灵”

比喻角色：被困在厨房里的厨神

小灵的特点：

  • 脑子里装着全世界的菜谱，读过万卷书
  • 能跟你聊美食哲学，回答任何烹饪问题
  • 但：没有腿，没有眼睛，没有手，没有钱
  • 只能在你提供的食材（你的提问）基础上加工（生成文字）

他的价值：餐厅的核心智慧，美味的来源
他的局限：困在厨房里，无法触碰现实世界

你能问他“鱼香肉丝怎么做”，但不能让他“去菜市场买根葱”。

Agent（智能代理）：全能店长“阿智”

比喻角色：指挥中心、决策大脑

阿智的任务：处理一个复杂目标——“用100块钱，做一顿让隔壁老王一家三口满意的晚餐”

阿智的工作流程：

阿智的核心能力：

  • 规划拆解：把大目标变成小任务
  • 决策判断：什么时候该做什么
  • 工具调用：知道自己做不到，但知道谁能做到

MCP（模型上下文协议）：万能插座“通通”

比喻角色：标准化的接口协议 + 通用说明书

为什么需要通通？

餐厅生意越来越好，阿智需要调用的工具越来越多：

  • 美团买菜、饿了么、京东到家
  • 计算器、日历、闹钟
  • 地图导航、支付系统

问题来了：每个APP的接口都不一样，对接一个学一个，阿智要累死了！

通通（MCP）的解决方案：

通通（MCP）的价值：

  • 统一接口：所有工具都按同一标准接入
  • 即插即用：新工具来了，直接插上就用
  • 上下文传递：把“100块预算”这个信息自动带给每个工具

通通让阿智从“学习每个工具”变成“只学通通一个”，效率飙升！

Skills（技能）：餐厅里的所有员工

比喻角色：真正动手干活的各个岗位

这是之前缺失的关键一块！ 没有 Skills，阿智只是“知道该干什么”，但没人真的去干。

我们的餐厅里有哪些员工（Skills）？

技能名称 岗位角色 具体职责
搜索技能 信息检索员 上网查“鸡翅当前价格”、“哪家超市便宜”
计算技能 会计 计算总价：鸡翅20 + 蔬菜8 + 鸡蛋5 = 33元
支付技能 收银员 完成线上支付，确保钱花出去
下单技能 采购员 在美团买菜上下订单，指定收货地址
日历技能 秘书 把“晚餐时间”记在日程上，设置提醒
地图技能 跑腿小哥 查询从餐厅到老王家的最佳路线
通知技能 通讯员 给老王发消息：“晚餐已在路上，30分钟到”

Skills 的特点：

  • 单一职责：每个技能只做一件事，但做到极致
  • 可复用：今天买鸡翅用采购技能，明天买鱼也用它
  • 标准化：都按照 MCP 的标准开发，插头一致

完整版：智能餐厅运转全流程

现在，让我们看看这四个角色如何完美配合：

四者关系全景图

一句话总结每个角色

概念 比喻角色 核心作用 一句话理解
LLM 厨神小灵 思考、生成 大脑——会想，但动不了
Agent 店长阿智 规划、决策 指挥官——知道怎么拆解任务、调用谁
MCP 插座通通 标准化连接 神经系统——让指令和数据无障碍流动
Skills 全体员工 具体执行 手脚——真正把事干了

核心思想

LLM 提供了智慧（能想）
Agent 提供了智能（会想怎么干）
Skills 提供了能力（能干）
MCP 提供了连接（让能干的事都能被调用）

用一句话说清楚整个系统：

Agent（指挥官）通过 MCP（万能插座）调用各种 Skills（专业技能），让 LLM（聪明大脑）的想法变成现实，完成复杂任务。

qt6的新特性

qt 版本历史

  • **Qt 1 系列 (1995-1998)**：这是Qt的起步阶段。首个公开版本于1995年发布，并在1996年随着KDE项目的采用，逐渐在Linux社区获得关注。
  • **Qt 2 系列 (1999-2001)**：Qt开始真正跨平台，发布了支持Windows的版本，并引入了QPL许可证。
  • **Qt 3 系列 (2001-2004)**：功能更加强大和成熟，增加了对Mac OS X的支持，进一步巩固了其跨平台能力。
  • Qt 4 系列 (2005-2015)：这是一个里程碑式的版本，对框架进行了重大革新，引入了模型/视图架构、QGraphicsView框架等强大功能。更重要的是，它在4.7版本中引入了QML和QtQuick，为声明式UI开发奠定了基础。这一时期Qt被Nokia收购，后又转至Digia。
  • Qt 5 系列 (2012-2020s)：标志着框架开发向开放治理的转变（qt-project.org）。它全面支持Android和iOS等移动平台，并引入了模块化的架构。此系列中的5.6、5.9、5.12、5.15等多个版本都是长期支持版本（LTS），被广泛用于各类生产环境。
  • Qt 6 系列 (2020-至今)：面向未来的版本，适应现代C++标准（C++17），优化了对Vulkan、Metal等下一代图形接口的支持，并在模块化方面做得更加彻底。其最新LTS版本是2024年10月发布的Qt 6.8，提供长达5年的商业支持，是当前开发新项目的首选。

如何选择Qt版本

面对众多的版本，你可以根据以下几点来决策：

  • 新项目首选：建议直接使用最新的 Qt 6 LTS 版本（如 6.8），它功能最新、支持周期最长，适合长期维护。
  • 维护老项目：如果你的项目基于Qt 5，可以继续使用对应的 LTS 版本（如 5.12 或 5.15），它们依然稳定可靠。
  • 考虑特殊需求：
  • 如果你的应用需要支持 Windows 7，请注意 Qt 5.15 是最后一个支持该系统的版本。
  • 对于嵌入式开发且对库大小有极致要求，一些开发者仍会选择成熟的 Qt 4.8.7。

  3. 在 Cline 面板中选择 “Anthropic”

  1. 访问 https://openrouter.ai/
  2. 注册并获取 API Key
  3. 在 Cline 中选择 “OpenRouter”
  4. 粘贴 API Key
  5. 选择模型（推荐 anthropic/claude-3.5-sonnet）

3.4 配置 DeepSeek

  1. 访问 https://platform.deepseek.com/

  2. 注册并获取 API Key

  3. 在 Cline 中选择 “OpenAI Compatible”

  4. 设置 Base URL: https://api.deepseek.com/v1

  5. 粘贴 API Key

  6. 模型 ID: deepseek-chat

8. 常见问题

Q1: API 调用失败怎么办？

可能原因：

  • API Key 无效或过期
  • 网络连接问题
  • API 额度用尽

解决方案：

  1. 检查 API Key 是否正确
  2. 检查网络连接
  3. 检查账户余额

Q2: Cline 执行了错误的操作？

解决方案：

  1. 使用 Git 回滚：git checkout .
  2. 在 PLAN MODE 下先确认计划
  3. 对危险操作说”不”

Q3: 如何让 Cline 更好地理解项目？

建议：

  1. 编写清晰的 README.md
  2. 使用规范的目录结构
  3. 在对话中提供足够的上下文

Q4: Cline 响应很慢？

可能原因：

  • 模型响应慢
  • 项目文件太多

解决方案：

  1. 使用更快的模型（如 DeepSeek）
  2. 配置 .clineignore 忽略大文件

Q5: 如何使用 MCP 扩展功能？

Cline 支持 MCP (Model Context Protocol)：

  1. 安装 MCP 服务器
  2. 在 Cline 设置中配置
  3. 可以访问更多工具和资源

  3. 善用 PLAN MODE 处理复杂任务
